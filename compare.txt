  4. Exemptions

  - Denton: ~60 dedicated columns on the property row — hs_exempt, ov65_exempt,
  ov65s_exempt, dp_exempt, dv1..dv4, dv1s..dv4s, ex_exempt, lve_exempt, ab_exempt,
  en_exempt, fr_exempt, ht_exempt, pro_exempt, pc_exempt, so_exempt, ex366_exempt,
  ch_exempt, eco_exempt, chodo_exempt, lih_exempt, git_exempt, dps_exempt, dvhs_exempt,
  dvhss_exempt, clt_exempt, ex_xa..ex_xv_exempt, ppv_exempt, dvch_exempt, dvchs_exempt,
  masss_exempt, frss_exempt, abmno_exempt, dstr_exempt, dstrs_exempt — plus
  exemption_percentage. Wide format, one column per exemption.
  - Tarrant: separate PropertyData_Exemptions file, 1-many, joined on account_num. Long
  format. Raw values are abbreviations that get mapped via
  tarrant_exemptions_abbrevation.csv → codes, then grouped per account into a single
  comma-joined exemptions string (scraping/2.generate_required_files.py:98-119,
  parsing/1.create_property_table.py:109-133).

  5. Canonical output shape (what each pipeline writes)

  - Denton lands the data essentially as-is — column list trimmed to ~140 but column names
  are preserved from the CAD feed. Output: denton.info (Parquet) + /mnt/denton/bronze/info
  (Delta), partitioned by load date.
  - Tarrant transforms into a downstream schema (property table). The final dataframe at
  parsing/1.create_property_table.py:300 has these columns:
  property_id, legal_description, type, zoning, address,
  neighborhood, neighborhood_cd, name, owner_id, mailing_address,
  perc_ownership, exemptions, year, id,
  owner_street, owner_city, owner_state, owner_zip, owner_fourdigit_zip,
  prop_street, prop_city, prop_state, prop_zip, prop_fourdigit_zip,
  living_area, lot_size_sqft, lot_size_acreage,
  owner_address_json, prop_address_json,
  names, lastName, owners_json, last_names, int_prop_id
  - Hard-coded fields: type='Real', zoning='Residential', prop_state='TX',
  perc_ownership='99%'. Owner names are parsed into owners_json with first/last splitting;
  addresses are emitted both as flat strings and as JSON objects.

  6. Practical differences to know

  - Different universe: Denton retains all property types and rich
  owner-snapshot/agent/confidentiality/rendition metadata. Tarrant pre-filters to
  residential A1 to A5 and discards anything outside that.
  - Different value model: Denton exposes the homestead/non-homestead split (land_hstd_val
  vs land_non_hstd_val, same for improvements) plus ag/timber and the 10% cap. Tarrant only
  has a single rolled-up improvement_value / land_value / total_value / appraised_value.
  - Different exemption model: Denton's wide one-column-per-exemption layout vs. Tarrant's
  long-form join + abbreviation mapping. Aligning them needs an exemption-code crosswalk
  before either can feed a shared homestead/bill table.
  - Different owner model: Denton ships three owner snapshots (py_* = primary/current,
  jan1_* = owner as of Jan 1, appr_* = appraised owner) plus confidentiality flags. Tarrant
  has one owner with the city+state mashed together in owner_citystate.
  - Different address quality: Denton already has structured situs (number, prefix, street,
  suffix, unit, city, zip). Tarrant has a single situs_address blob and no situs zip; the
  pipeline back-fills prop_zip from owner_zip when streets match
  (parsing/1.create_property_table.py:234).
  - Different deed identifier: Denton uses deed_book_id/page + deed_num; Tarrant uses
  deed_book/page + instrument_no. Same idea, different field names.
  - Entities vs. taxing jurisdictions: Denton lumps them into one entities string + a
  separate appraisal_entity_info.txt file. Tarrant lays them out as named columns (county,
  city, school, spec1..spec5), so jurisdiction breakdown is easier in Tarrant but loses
  ordering/IDs that Denton keeps.
  - Improvements/land detail location: Denton has them in separate files
  (appraisal_improvement_detail.txt, appraisal_improvement_info.txt, land_detail.json) —
  info.txt itself does not carry living_area or year_built. Tarrant carries living_area,
  land_sqft, land_acres, year_built on the property row, with extra residential
  attribute/feature files joined later.

  Net: Denton's property feed is wider and more granular (more owner snapshots, structured
  situs, per-exemption flags, h-stead splits, agent/confidentiality/rendition); Tarrant's is
   narrower and pre-aggregated but already pre-filtered to residential and already includes
  living area / year built on the property row. Any unified model needs to reconcile (a)
  value composition, (b) exemption representation, (c) owner snapshot semantics, and (d)
  entity/jurisdiction shape
